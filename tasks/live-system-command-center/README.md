# JARVIS LIVE SYSTEM — отдельная задача

Статус: этап 1 — изолированный 3D-прототип и контракт данных.

## Цель
Сделать встроенную в главное окно Windows-приложения интерактивную 3D-карту реальной структуры и активности JARVIS: модули, агенты, процессы, рабочие папки, задачи и сделки.

## Принципы
- Это рабочая карта, а не заставка. Каждый узел должен иметь стабильный ID и источник данных.
- Цвет отражает состояние/нагрузку, размер — нормализованную нагрузку, импульсы на рёбрах — передачу событий.
- Демоданные всегда явно помечаются DEMO. Нельзя выдавать их за реальную телеметрию.
- Существующий Three.js Reactor сохраняется; новая карта — отдельный режим/слой внутри главного окна, не отдельное окно браузера.
- Backend остаётся источником истины. UI только визуализирует полученные данные.
- Никаких CDN-зависимостей: использовать уже встроенный локальный Three.js.
- Никаких фиктивных показателей CPU/GPU/RAM. Неизвестные значения показывать как «нет данных».

## Структура узла
`id`, `type`, `label`, `status`, `load` (0..1 или null), `metrics`, `updated_at`, `source`.
Типы: `root`, `folder`, `agent`, `process`, `task`, `deal`, `module`, `resource`.
Статусы: `idle`, `active`, `busy`, `warning`, `error`, `offline`.

## Цветовая семантика
- cyan — активность/передача данных;
- green — штатная работа;
- yellow — предупреждение/средняя нагрузка;
- orange — высокая нагрузка;
- red — ошибка/критическое состояние;
- slate — неактивен/нет данных.

Нагрузка и состояние — разные измерения: активный узел не обязательно перегружен; ошибка всегда имеет приоритет цвета.

## Этапы
1. Изолированная папка задачи, спецификация и интерактивный Three.js-прототип.
2. Backend endpoint на loopback, реальные процессы/ресурсы и безопасный ограниченный каталог проектов/папок.
3. События агентов, задач и сделок через единый реестр событий.
4. Встраивание в главное окно без запуска системного браузера.
5. Автотесты, проверка производительности, Windows EXE smoke test.
